# QCTO Form 5, section 4: Hybrid / blended mode of delivery → LMS mapping

Section 4 is compulsory for SDPs using online, distance or hybrid/blended delivery. Every item needs a Yes/No **and** a narrative of evidence. This table maps each item to the LMS feature that answers it and the evidence document we will produce.

**Rule:** every LMS feature PR updates this file. Change a row's status from `planned` → `in progress` → `implemented` → `evidence ready`, and link the evidence document.

Row IDs (4.1.1 etc.) are our own numbering of the bullets, in the order they appear on the form.

## Readiness dashboard and evidence pack (2026-11-09)

- **Form 5 readiness dashboard** (`/admin/form5`; read-only for external evaluators at `/staff/evidence/form5`): one row per item above, with a status computed from live data (✓ Ready · ! Needs attention · ▢ Manual document needed · – Not applicable), the figures behind it and links to the evidence (`lib/server/readiness.ts`, `lib/form5.ts`).
- **Evidence pack**: one combined PDF with a contents page: dashboard snapshot, assessment schedule, a sample randomised paper (answer keys only in evaluator exports), a sample moderation report, a communication log sample and the backup and restore log. Learners are pseudonymised; each export's SHA-256 is audited (`lib/server/evidencePack.ts`).
- **DEMO walkthrough**: `yarn workspace db db:seed` then `yarn workspace lms demo:evidence` gives the DEMO cohort real evidence for every live item (assessments sat, marked, moderated and released; communication, sessions, notes; the 4.4 reference; a restore test; a backup when `BACKUP_ENCRYPTION_KEY` and storage are set). Tested in `apps/lms/test/form5.test.ts`.
- **QCTO submission panel** (`/admin/qcto`): incomplete profiles, validation errors, unsent enrolment submissions, EISA readiness due, last submission batch, accreditation warnings.
