## 1. File-level rules

Where the two sources differ, the template's Instructions sheet is quoted and the PDF rule is noted in §3.

| Rule             | Rule applied (source)                                                                                                                                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Two stages       | One file per batch of learners per full or part qualification, submitted in two stages (template A12). **Decided:** one batch = one cohort.                                                                                                                                                                            |
| Stage 1          | Complete columns A–AJ and the date stamp AQ; send to **Learnerenrolments@qcto.org.za** within **21 days after the start date of training** (template A13).                                                                                                                                                             |
| Stage 2          | Update columns AK–AP and the date stamp AQ; send to **EISAreadiness@qcto.org.za** **at least 3 months before** the anticipated EISA date (template A15).                                                                                                                                                               |
| File name        | `LEISAyyyymmdd-SDP/AC name`. yyyymmdd = date the file was updated; the name is the institution's name as on the accreditation letter and **may be shortened/abbreviated** (template A18).                                                                                                                              |
| Sheets           | Two sheets, names kept exactly: `1 - Instructions`, `2 - Learner Enrolment and EISA.` The Instructions text itself calls them "Instructions" and "Learner Enrolment and EISA" (no number, no full stop); the real sheet names win.                                                                                     |
| Format           | Excel only; never converted to PDF or another format (template A12, PDF p6).                                                                                                                                                                                                                                           |
| Columns          | Fixed headers (§2, exact text from row 1 of sheet 2) and order; no column deleted or moved (PDF p6). Row 1 has an autofilter over `A1:AQ1`.                                                                                                                                                                            |
| Cell type        | **All data entered as TEXT**; no %, General, custom, date or number formats (PDF p8). The template does not fully follow this: its header row and the pre-formatted rows 2–11 of columns D, E, G, J–N, AB, AD, AE, AG, AH and AK are formatted _General_. The exporter sets text format (`@`) on every cell it writes. |
| Compiler details | Instructions rows 21–30 ("DETAILS: (COMPULSORY INFORMATION)"): label in A:C, value in the merged cells D:M. See §2.2.                                                                                                                                                                                                  |
| Accreditation    | Dates of capturing, achievement or reporting are valid only inside the SDP's and the qualification's accreditation periods (PDF p4). **Decided:** outside either period blocks the download.                                                                                                                           |
| Universal rule   | Almost every column: "the first character of the data value is a valid, non-space character" (PDF, all columns).                                                                                                                                                                                                       |
| File properties  | The template's hidden properties name QCTO staff (author, last modified by) and a QCTO file-server path. **Decided:** generated files replace these with the provider's name from provider settings (white-label: never hard-coded) and drop the path. The template in `qcto/` stays unchanged.                        |
| Embedded content | This template has **no image, drawing or logo**. Its package does hold an unreferenced `[trash]/0000.dat` part (2.6 KB, almost all zero bytes), plus SharePoint `customXml` parts and printer settings. The exporter must keep everything that is referenced; the fidelity test covers this.                           |

## 2. Column mapping

### 2.1 Sheet `2 - Learner Enrolment and EISA.` (A to AQ)

- **Header**: exact text of row 1 in the template. The PDF field names (prose, e.g. "SDP Code") are not used in the file.
- **Stage**: 1 = filled and validated in the stage 1 file; 2 = filled and validated in the stage 2 file. **Decided:** in a stage 1 file, AK–AP are left empty and not validated. A stage 2 file holds all columns, with A–AJ refreshed from current data (§5).
- **Required**: the PDF label (I-1 explains `Yes – QCTO`), then the rule the LMS applies.
- **LMS source**: the table or column in `packages/db`. **Collected now?**: _Yes_ = learners or staff enter it through a screen today; _Schema only_ = the column and constraints exist but no screen writes it yet; _No_ = nothing exists.
- Character sets are quoted from the PDF. "Letters" means A–Z and a–z only.

## 5. Decisions (2026-11-08)

| Topic                   | Decision                                                                                                                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Readiness type (AN)     | GRIT Hub trains in **mixed mode: code 3** for a ready learner it trained. | Stage 2 columns A–AJ    | Re-read from **current data**, so corrections since stage 1 reach the QCTO. Same learners and row order as the linked stage 1 batch; the register lists which columns changed per row (no values).                                                                                        |

## 6. New fields and records to collect

Learner profile fields (C–AI) are already collected by the setup profile step. What is still missing:

**Provider settings** (one row per tenant; extends `provider_accreditations`):

- Short name for the file name (optional; defaults to the legal name)
- Institution phone number, SDP physical address and SDP province (Instructions rows 24, 29, 30)
- Default readiness type for a ready learner (GRIT Hub: 3)
- Screens to manage the legal name, SDP code, accreditation number and SDP accreditation dates (columns exist; no screen)
- Per qualification: accreditation start and end dates (`qualification_accreditations` exists; no screen), and the QCTO qualification ID (`qualifications.saqa_id`, I-28)
- Assessment centres (`assessment_centres` exists; no screen)

**Per cohort:** scheduled EISA date and assessment centre (columns exist; no screen).

**Per learner per enrolment** (`enrolment_qcto_records` exists; no screen):

- Readiness type (AN), SOR status and issue date (AK, AL)
- FLC code and evidence number (AO, AP): certificate number, FLC statement of results number, or `RPLyyyymmdd`; 06 "not applicable" at NQF 5+

- Stage (exists as `purpose`: `enrolment` = stage 1, `eisa_readiness` = stage 2); cohort required (today nullable)
- Link from a stage 2 batch to its stage 1 batch (new)
- Compiler name, email and phone (new)
- Mailbox used (new; stage 1 learner enrolments, stage 2 EISA readiness)
- Sent at and sent by (exist as `submitted_at`, `submitted_by`)
- QCTO acknowledgement: date and reference (new reference field; `responded_at` and `response_note` exist)
- Per learner: left out of stage 2 and why (new), and which columns changed since stage 1 (new, column letters only)
- File hash, row count, generated by and at, status (exist)
