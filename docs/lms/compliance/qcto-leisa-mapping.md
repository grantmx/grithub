# QCTO LEISA file: column mapping

Status: **draft for review** (Step 1, read-only analysis).
Source: QCTO _Data Load Specifications for SDPs and ACs on the Population and Submission of the Learner Enrolment and Readiness for EISA File_, developed May 2022, effective 1 June 2022 (27 pages). Page numbers below refer to that PDF. The PDF itself is not in the repo.

> **Get the current official Excel template from the QCTO** (learnerenrolments@qcto.org.za or your QCTO contact) before building the exporter. The spec gives field names but **not the exact header text** of the template (for example, column AP is written `FLCStatementofresultnumber`, which looks like a header, while the others read like prose names). Where the template and this spec differ, **treat the template as authoritative** and update this document.

No real learner data and no real QCTO-issued codes appear in this repository. Examples below are synthetic.

## 4. Fields the LMS must newly collect

The committed LMS has only: display name (one string), sign-in email, POPIA notice acceptance with timestamp, cohorts (start/end dates), qualification code and NQF level, and assessment decisions.

**Per learner (QCTO profile):**

- Title (R); first, middle and last name exactly as on the ID (P, Q, O)
- National ID (C) or alternate ID (D) and its type (E): **encrypted**
- Birth date (S): encrypted
- Equity (F) and disability status and rating (L, M): **special personal information, encrypted**
- Nationality (G), home language (H), gender (I), citizen resident status (J), socioeconomic status (K), immigrant status (N)
- Home address 1–3 and postal code (T, U, V, Z); postal address 1–3 and postal code (W, X, Y, AA): encrypted
- Phone, cell, fax (AB–AD): encrypted; whether to share the sign-in email (AE). Fax isn't asked (optional column)
- Province (AF) and Stats SA area (AG)
- A separate, versioned consent to share with the QCTO, giving POPI Act Agree and Date (AH, AI)

**Per learner per enrolment:**

- Readiness for EISA type (AN)
- SOR status and issue date (AK, AL): derived from decisions, plus the issue date when the SOR is issued
- Expected completion date override (AJ)
- FLC code and evidence number (AO, AP)
- AP-led RPL override for the SDP code (A) where applicable

**Per provider / cohort (configuration):**

- SDP name as on the accreditation letter, SDP code (or accreditation number), SDP accreditation start and end dates (A, file name)
- Accreditation start and end dates per qualification (overview rule)
- Assessment centre code (AM) and scheduled EISA date per cohort (AL check, readiness deadline)
- Stats SA area code list (imported from an official Stats SA file, not invented)

> Note: the schema in `packages/db/src/schema/qcto.ts` (migrations 0008, 0009, 0012, 0013; ADR-014) has been reconciled with this mapping. It covers the I-6/I-7 ID-type rule, the I-15 email choice, the I-27 SDP code override, a separate QCTO sharing consent (AH/AI), and FLC 06 exactly at NQF 5+. The validation rules marked + and the I-x proposals that need decrypted values or decisions belong to the LEISA exporter (Step 2).
